# Статическая клиентская демонстрация на Vercel

## Цель

Добавить в существующий репозиторий самодостаточную статическую сборку, которую Vercel сможет показать клиенту по публичной ссылке без WordPress, PHP и базы данных.

## Выбранная архитектура

- Папка `global-english/` остаётся единственным источником дизайна, контента и поведения WordPress-темы.
- Локальный экспортёр получает HTML из существующего `tests/preview.php` для трёх маршрутов и сохраняет очищенные статические страницы в `vercel-demo/site/`.
- Vercel запускает Node.js-сборщик из корня репозитория. Сборщик копирует статические страницы и актуальные ресурсы темы в `vercel-demo/dist/`.
- Корневые `package.json` и `vercel.json` задают команду `npm run build` и output directory `vercel-demo/dist`.
- `vercel-demo/dist/` генерируется заново и не хранится в Git.

## Публичные маршруты

- `/` — полный лендинг.
- `/privacy-policy/` — политика конфиденциальности.
- `/data-consent/` — согласие на обработку данных.

Внутренние ссылки переводятся с PHP preview URL на эти чистые маршруты. Ссылки на секции, телефон, почту и Telegram руководителя сохраняются.

## Ресурсы и обновление

- CSS, JavaScript, шрифты, SVG, PNG и WebP копируются из `global-english/assets/` в `dist/global-english/assets/`, поэтому существующие абсолютные пути продолжают работать.
- Скрипт экспорта не запускается на Vercel: он используется локально после изменений PHP-шаблонов, а готовые HTML-снимки коммитятся.
- Сборка Vercel не зависит от PHP и внешних npm-пакетов.

## Формы

- Поля, маска телефона, клиентская валидация и модальное окно работают как на основном сайте.
- Валидная отправка перехватывается статическим demo-скриптом.
- Демонстрация не сообщает об успешной отправке письма. Она показывает сообщение, что онлайн-отправка подключается на рабочем домене, и предлагает позвонить по подтверждённому номеру.
- Никакие имена и телефоны посетителей не передаются наружу и не сохраняются.

## SEO и доступность демо

- Все страницы получают `noindex, nofollow`, поскольку это клиентская демонстрация, а не рабочий домен.
- Заголовки страниц, один `h1`, семантика, клавиатурное управление, focus-состояния и reduced motion сохраняются.
- `robots.txt` запрещает индексацию всего preview-сайта.

## Рассмотренные варианты

1. Статический снимок в этом репозитории — выбран: полностью воспроизводит интерфейс, не требует WordPress-сервера и быстро разворачивается на Vercel.
2. PHP community runtime — отклонён: сам по себе не предоставляет WordPress, базу данных, загрузки и административную часть.
3. Headless WordPress с отдельным Next.js-фронтендом — отклонён для клиентского просмотра как избыточный; подходит для отдельного производственного проекта.

## Проверка

- Контрактные тесты подтверждают отсутствие localhost, `.php`-ссылок и действующего POST endpoint в статических страницах.
- `npm run build` создаёт три маршрута, `robots.txt` и полный набор локальных ресурсов.
- Браузерный QA проверяет главную и юридические страницы на ширинах 1280, 768, 360 и 320 пикселей, меню, модальное окно, формы, прайс, Cookie, отсутствие ошибок и горизонтального переполнения.
- После QA изменения коммитятся и отправляются в `origin/main`; Vercel Deployment выполняется пользователем через Import Git Repository.

## Настройки Vercel

- Repository: `rez1dennt/global-english`.
- Root Directory: корень репозитория.
- Framework Preset: `Other`.
- Build Command и Output Directory берутся из `vercel.json`; вручную их менять не требуется.
- Production Branch: `main`.

## Внешние ограничения

Демо не заменяет WordPress-хостинг и не подключает отправку писем. Для рабочего запуска по-прежнему нужны ссылки менеджера в Telegram и MAX, утверждённые документы, реальные фотографии и отзывы, а также настроенный почтовый транспорт.
